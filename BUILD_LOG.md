# Build Log

## 2026-09-18 — Homepage v1

**Scope:** Full homepage build from `tecknotrove_wireframe.xlsx` (sheet "1. Homepage") and `Tecknotrove Brand Book.pdf`, per user request for an immersive, non-generic, scroll-animated site.

**Stack:** Next.js 16 (App Router, Turbopack) · TypeScript · Tailwind v4 · Lato + JetBrains Mono (next/font/google) · GSAP + ScrollTrigger · Lenis (smooth scroll) · Motion (motion/react) · @phosphor-icons/react.

**Sections built (in order):** Nav (dark, mega-menu overlay) → Hero (full-bleed brand-blue, radar/grid motif, curtain-reveal into next section) → Sector bento grid (Defence/Aviation/Automobile/OESD, asymmetric 4-cell layout) → Stat strip (cream, GSAP count-up) → Why Tecknotrove (parallax full-bleed photo, GSAP scrub) → News & Insights (horizontal scroll-snap gallery) → Partner/Careers (2-tile gradient split) → LinkedIn (60/40 split, dark blue panel) → Callout (orange band) → Footer (black).

**Color pass:** Initially built dark-cinematic; user supplied an explicit section-color legend mid-build (Nav=charcoal, Hero=blue, Stat strip=cream, cards=white/light-grey/light-blue, CTA=orange, Footer=black) plus the brand palette swatch. Re-themed all sections to match via CSS custom properties in `globals.css`; kept dark "islands" (Nav, Footer, the two dark accent panels) as deliberate, brand-book-consistent exceptions to the otherwise light page theme.

**Imagery:** No image-gen credits available (OpenAI/Gemini both quota-exhausted). Client's Aviation/Defence/Driving asset folders were empty OneDrive cloud placeholders; only `OESD/IMAGES` had real photos (used for the OESD sector card and the "Why Tecknotrove" parallax background). Replaced initial `picsum.photos` stock-photo placeholders (News, Partner/Careers) with brand-gradient + Phosphor-icon cards after visual QA caught irrelevant random photos (a dog for "Careers") and per the brand book's explicit ban on staged stock imagery.

**Bug fixed — scroll-reveal reliability:** Motion's `whileInView` left some elements permanently stuck at their hidden `initial` state (confirmed via computed styles, not just screenshots). Replaced with a custom `useInView` hook (native `IntersectionObserver` + a debounced scroll-settle safety net that force-reveals anything the viewport has already reached). Verified via `getComputedStyle` checks under aggressive/fast scroll conditions post-fix. Full detail in memory: `feedback_scroll_reveal_reliability`.

**Verified:** `tsc --noEmit` clean, dev server error log clean, mobile viewport (375px) checked, content order/copy checked via `get_page_text`.

## 2026-09-18 — Interaction pass (buttons, sector fan, folder cards)

**Buttons:** unified every button on the site into `MagneticButton` (nav CTA, hero, callout, floating Enquire). Uiverse-style left-to-right sweep fill on hover, solid brand orange (no gradient). Added a `sweep` prop so buttons on the orange callout band sweep brand blue instead (orange-on-orange was invisible).

**Sector cards:** replaced the bento grid with a scattered row + mousemove "fan" interaction (GSAP): random per-load tilt, elastic staggered scroll-in, hovered card straightens + scales while neighbours' faces slide away proportionally (`22 / (index - active)`), re-scatters on leave.

**Bug fixed — fan appeared dead:** the interaction was gated at `min-width: 768px`, but the preview pane is 732px, so it silently fell back to the stacked mobile layout. Lowered the row + fan to `640px`, tightened card padding/type below `lg`, and hid the card description below `lg` so narrow cards don't get cramped. Also changed the GSAP matchMedia gate from `prefers-reduced-motion: no-preference` (which killed the whole interaction for reduced-motion users) to a conditions object that keeps the interaction but shortens durations and drops the random jitter. Added a global reduced-motion CSS rule collapsing transition/animation durations.

**News cards (folder cards):** rebuilt to match the reference behavior, verified frame-by-frame from a client screen recording (extracted with OpenCV since ffmpeg isn't installed). Correct mechanic: the notched foreground panel **slides down ~120px on hover** to reveal the artwork behind it, the number rides down with the panel, and the title/meta stay anchored to the card bottom (they're a separate absolutely-positioned layer, not inside the panel). Notch is a CSS radial-gradient corner piece, not an image.

**Folder-card shape corrected (second pass):** the notch is NOT a bite out of the top-left corner. Zooming the reference frames 3x showed it is a true **folder tab** — the panel's left ~38% is raised with rounded top corners, then steps down via an S-curve (convex on the tab, concave on the joint) to the lower body which runs to the right edge with a rounded top-right corner. Measured geometry: tab top 20% of card height, body top 28%, tab width 38%, radius 14px, hover drop 22%. Built from three same-colour blocks (tab / concave joint / body) plus a radial-gradient corner for the concave fillet; the whole group translates together on hover while the copy stays pinned to the card bottom.

**Card styling:** blue / grey / black variants, each with an outer frame (`p-[7px]` in a darker tone of the card colour), `aspect-[4/5]`, large number, arrow, title + meta. Row moved into the same `max-w-[1400px] px-5 sm:px-8` container as the heading and switched from a full-bleed horizontal scroller to `grid sm:grid-cols-3`, so left/right padding is now equal instead of left-aligned. Headlines shortened to 2 lines so the number doesn't crowd the copy when the panel drops.

**Folder-tab shape, third pass (final):** the border-radius construction still read as a blocky step. Zooming both the reference and my render 4-7x showed why: quarter-circle corners force the edge to reach fully vertical, leaving a straight vertical wall between the convex and concave corners. The reference has no such wall — its two arcs meet directly at an inflection point, so the step reads as one continuous ~45 degree S-ramp. Replaced the three-div construction with a single SVG `path` (viewBox `0 0 400 500`, `preserveAspectRatio="none"` — safe because the card is locked to `aspect-[4/5]`, so it scales without distortion). Final shape uses a **straight diagonal** for the step (not arcs meeting at an inflection): tab edge runs to x=146, a short quadratic eases into a straight ~50 degree slant from (159,109) to (177,131), then another quadratic eases back onto the body edge at x=190. Two arcs meeting at an inflection still read as "curved"; the reference clearly has a straight slanted segment.

**LinkedIn section rebuilt:** swapped the layout — account details now on the left (label, headline, logo tile + company identity, followers / countries stat row, hashtags, follow button, view-all link), and the two most recent posts on the right as a **stacked polaroid deck**. Polaroid treatment is a white frame with a thick bottom margin, sharp 3px corners (deliberately different from the rounded cards elsewhere so they read as photos), a 4:3 tinted plate per post carrying the category colour and chip, and the post text plus `N days ago · N reactions` in the bottom margin. Cards are absolutely positioned and counter-rotated (-6 / +3 deg); hovering the deck separates and straightens them so both become readable. Below `sm` they fall back to a straight vertical stack with no rotation. Card width capped so the deck doesn't dominate in the single-column range between `sm` and `lg`. Sizes were then scaled up on both sides: polaroids to `sm:w-[78%] sm:max-w-[440px]` (deck height 540px), and the account column to a `text-5xl` headline, 64px logo tile, `text-4xl` stat figures and larger pills/links, with the grid evened to `lg:grid-cols-2`. Per-card hover added on top of the group separation — `hover:z-30` plus `hover:scale-[1.05]` on each card (base `z-10` / `z-20`), so whichever card the cursor is on lifts above the other. Verified by reading computed `z-index` and `scale` during a live hover rather than by eye, since the preview pane's screenshot coordinates don't map 1:1 to viewport pixels.

**Stat strip tightened:** the four figures were spreading across the full 1336px container with ~180px gaps, and the cream band was ~285px tall. Capped the stats block at 980px (gaps down to ~40px), cut section padding from `py-14/18` to `py-8/10`, and moved the "Know more" link from a row underneath to the right-hand end of the stats row (`md:flex-row md:items-center md:justify-between`) — which both fills the empty right side and removes a whole row. Band is now 158px tall, down from ~285px. Below `md` it falls back to the 2x2 grid with the link underneath.

**Closing CTA band revamped:** was a flat centred slogan on a large orange slab with a lot of dead vertical space. Rebuilt as an asymmetric split: pitch on the left (headline broken to two lines, subtext, "Book a demo" + "Download Brochure"), and a dark inset facility card on the right carrying the real contact details from the brand book — registered name, the Mumbai address, phone and website, plus a Mon-Sat / 24x7 row. Padding cut from `py-28/36` to `py-20/24`; the card now fills what used to be empty space rather than the band just being taller. Stacks vertically below `lg`.

**Open item:** "Book a demo" points at `tel:+912261513002` because there is no contact form yet, and the earlier `mailto:info@tecknotrove.com` was an invented address — swap in the real enquiry destination when it exists.

**Real photography sourced from the brochures:** installed PyMuPDF and pulled imagery out of the sector brochure PDFs, which resolves the long-standing "no real photos" gap (the Aviation/Defence/Driving IMAGES folders are empty OneDrive placeholders and image-gen credits are exhausted). Embedded images turned out to be mostly whole brochure pages, so the usable route was to render cover pages at 300 DPI with `get_pixmap` and crop the hero photo band (`y 0.168-0.564`) and the three-up simulator strip (`y 0.573-0.735`) by normalized coordinates. Exported: `sector-defence` (tank, cropped from the Tank Driving spread), `sector-aviation` (cargo high loader), `sector-automobile` (HMV trucks), `sector-oesd` (excavator), plus `news-army` (uniformed operator in a sim), `news-expo` (expo booth rig) and `news-motion` (truck cab on a motion platform). All under 175KB.

Sector cards now use the photo full-bleed behind a tuned light scrim (opaque to 44%, clear by 100%) so the dark copy stays readable while the top half of the photo reads clearly — the earlier flat `via-bg-panel/85` washed the photos out. The abstract grid/sweep/stripe treatments and the per-card `visual` switch are gone. News folder cards drop the Phosphor icon for the photo on the plate, which the sliding panel reveals on hover. Removed the three unused OESD simulation-render JPGs.

**LinkedIn section wired to the real account:** company URL is `linkedin.com/company/tecknotrove-systems-i-pvt-ltd`. Replaced the invented posts with the two most recent real ones (coal-mine training incident cost; operator time-to-competency), each polaroid now deep-linking to its own post permalink in a new tab, with a LinkedIn badge on the plate. Both permalinks were fetched and confirmed to return HTTP 200 with matching post text before going in — worth repeating if they are ever swapped, since a dead permalink is invisible until someone clicks. Follower count corrected from an invented 12,400+ to the verbatim 9,232, company name to the registered "Tecknotrove Systems (I) Pvt Ltd", and the Follow / View-all links point at the real profile instead of `linkedin.com`. Plates use two fresh mining-simulator crops (`li-post-mining`, `li-post-training`) matching the posts' subject matter.

Post dates are shown as month-level ("Sep 2026") rather than the relative "2d / 5d" LinkedIn renders, since relative dates on a static page go stale.

**Rebuilt as authentic LinkedIn post cards (per explicit request):** the polaroid treatment was swapped for a real LinkedIn-style card: profile row (company logo, name, follower count, time, globe icon), post text, the real document cover image, a document title/page-count bar, reaction count, and a Like/Comment/Repost/Send action bar (icons only — no fake counts for comment/repost since neither was visible on the source page). Real post media (the actual 4-page document cover images, not stand-in photos) was pulled by fetching the raw post-page HTML directly with `curl` and grepping for `media.licdn.com` document-cover URLs — the WebFetch-agent route strips `<meta>`/`<img>` tags during its markdown conversion, so og:image and inline image src values don't survive it. Downloaded: `li-post-1.jpg`, `li-post-2.jpg` (real post covers), `li-logo.png` (real company logo, from a `company-logo_100_100` DMS URL). These signed DMS URLs carry an expiry (`e=` param) baked into the querystring, so they had to be downloaded immediately, not just linked.

**Fixed:** the initial stacked layout used a heavy percentage-based overlap (copied from the polaroid version), which is fine for photos but made overlapping post text unreadable, defeating the point of a redirect-through card. Changed to a small fixed-pixel corner-peek (44px/52px offset, `-rotate-1`/`rotate-1`) so both cards are fully readable at rest; hover still separates and lifts the hovered card to the front (z-30, shadow deepens).

**Gotcha:** Tailwind cannot generate utilities from template literals (`group-hover:translate-y-[${SLIDE}%]` silently produces no CSS) — the hover-drop class must be a literal.

**Verified:** `tsc --noEmit` clean, fresh-tab console clean, fan confirmed numerically at both 732px and 1440px, folder-tab geometry confirmed numerically (tab 20%/38%, body 28%) and the slide confirmed visually.
